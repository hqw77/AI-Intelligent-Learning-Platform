# 阶段 1：全局地图 —— yu-ai-learn

## 一句话定位

**AI 闯关学习微信小程序**：用户输入一句话（或上传私有文档/网址），AI 联网搜索或检索知识库，自动生成一组闯关题目，用户边答边学，通关后拿到 AI 复盘报告并积累经验值。

## 技术栈速览

| 层 | 技术 |
|---|---|
| 前端 | Taro 4 · React 18 · TS · Sass（微信小程序） |
| 后端 | Python 3.11+ · FastAPI · Pydantic v2 · asyncio |
| AI 编排 | LangChain · LangGraph |
| 模型/检索 | DeepSeek（出题/报告/Agent）· 阿里云百炼（Embedding/文生图）· Tavily（联网搜索） |
| 向量库 | Chroma |
| 存储 | MySQL（aiomysql 异步池）· 腾讯云 COS |
| 鉴权 | 微信 jscode2session 静默登录 + JWT |

## 四条主链路

### 链路 1：出题（核心，面试必讲）

```
前端输入一句话
  → POST /quiz/generate/async（异步任务模式）
  → quiz_service.create_quiz_task（敏感词过滤 + 校验 + 建 task 记录）
  → asyncio.create_task 后台 _run_quiz_task
       → _fetch_context 选资料来源：
           ├ 有 doc_id → rag_service.fetch_rag_context（Agentic RAG）
           └ 无 doc_id → search_service.fetch_knowledge_context（联网 Agent）
       → generate_quiz（quiz_chain，DeepSeek 结构化输出 JSON）
       → 可选 image_service.generate_images_for_quiz（配图）
       → 落库 quiz_repository.save_quiz_session
       → 更新 task 状态 completed
  → 前端 pollQuizTask 轮询 → 跳答题页
```

**关键设计点（面试会问）**：
- 为什么用「异步任务 + 轮询」？因为联网搜索 + LLM 出题耗时长（几十秒），同步会超时。
- 为什么用 Agent（LangGraph ReAct）而不是单次 LLM 调用？让 AI 自主决定搜什么、搜几轮。
- 为什么「配图失败不阻塞」？成本控制 + 主流程优先。

### 链路 2：答题 + 报告

```
答题页本地判分（单选/多选/判断）
  → 全部答完 → POST /report/generate
  → report_service.handle_report_generate
       → scoring_service.compute_score_summary（计分聚合）
       → generate_report（report_chain，DeepSeek 生成报告）
       → 落库（答题记录 + 报告 + 经验值 +10/+2每题）
```

### 链路 3：知识库 RAG

```
上传文档 → knowledge_service.handle_upload（格式/大小/数量校验）
  → 后台 _process_document
       → document_loader_service.load_and_split（PyPDFLoader/Docx2txtLoader/TextLoader + RecursiveCharacterTextSplitter 分块）
       → vector_store_service.add_document_chunks（百炼 Embedding → Chroma，每用户一个 collection）
       → 状态置 ready
  → 出题时 rag_service Agentic RAG 检索（向量检索工具 + 可选联网工具，Agent 决定何时补充）
```

**关键设计点**：每用户一个 Chroma collection（`kb_user_{user_id}`），检索按 `doc_id` 过滤，实现数据隔离。

### 链路 4：用户登录

```
前端 wx.login 拿 code → POST /user/login
  → user_service.handle_login
       → jscode2session 换 openid
       → 查/建用户
       → create_token（JWT，30 天）
  → 后续请求 Authorization: Bearer token（get_optional_user 可选鉴权）
```

**关键设计点**：`get_optional_user` 可选鉴权——未登录也能完整体验核心流程（出题/答题），登录才落库+经验值。

## 前端页面

| 页面 | 作用 |
|---|---|
| pages/index | 输入学习内容 → 异步出题 → 轮询 → 跳答题 |
| pages/quiz | 答题（本地判分、即时讲解、AI 配图展示） |
| pages/report | 复盘报告（掌握度/薄弱点/总结/建议） |
| pages/knowledge | 知识库文档上传/列表/删除 |
| pages/profile | 个人中心（经验值/历史闯关/报告回看） |
| services/api.ts | API 封装 + 类型 + 登录就绪机制 |

## 下一步（阶段 2 精读顺序）

按价值排序，建议精读顺序：
1. **出题链路**（LangGraph Agent + 结构化输出）—— 含金量最高
2. **RAG 链路**（文档解析 → 向量化 → Agentic 检索）
3. **异步任务 + 轮询**（架构设计）
4. **配图链路**（成本控制 + 降级容错）
5. 用户鉴权（JWT + 可选登录）
